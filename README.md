# ChooseYourContent - 볼 콘텐츠 정하기

## 9주차 폼 UI와 입력 경험 설계 구현 기록

## 수정 사항
- 찜 목록 이름 입력 항목에 label과 도움말을 연결함.그 외 입력 항목에도 label을 연결함.
- 찜 목록 이름 입력 항목에 입력 조건(2자 이상)을 추가함.
- 추가 카테고리 선택 체크박스가 있는 영역(콘텐츠 추가 및 콘텐츠 선택)을
    선택함에 따라 추가 입력 영역이 나타나거나 사라지도록 구현함.
- 추가 카테고리의 입력 요소는 disabled로 비활성화하고, 다시 표시되면 사용할 수 있도록 처리함.
- 정보 활용 동의 여부를 form 의 submit 이벤트로 제출을 처리함.
- 그 외 기타 사항 수정

## 인터렉션 시나리오
1. 정보 수집 및 활용 안내
- 기존의 흐름에서 동의 여부가 저장 완료 됐을 때 다른 버튼들이 확인 버튼으로 대체됨.
    저장 중에는 시작 버튼이 비활성화 됨.
    취소 시 초기 상태(비활성화)로 돌아감.
    확인 버튼을 누르면 찜 목록 작성 화면으로 넘어감. 이후 화면을 새로고침 해도 찜 목록 작성 화면이 나타남.

2. 찜 목록 이름 설정
- 행동, 이벤트: 이름을 적고 '목록 만들기' 를 클릭한다.
- 조건: 앞뒤 공백을 지운 제목이 2자 이상인가?
- 반응, 다음 상태: 입력 값이 몇 자 인지 표시해줌.
                2자 이하라면 같은 화면에 오류를 표시하고 입력창에 초점을 둔다.
                2자 이상이면 입력 항목의 배경색과 조건 충족을 알리는 안내 문구가 나타남. 수정 시에도 동일하게 적용됨.
                이하 이전과 동일함.

3. 콘텐츠 제목 입력
- 이전과 동일.

4. 분류 및 카테고리 선택
- 행동, 이벤트: 카테고리를 선택하고 '찜 목록에 콘텐츠 추가하기' 를 클릭한다.
- 조건: 추가 카테고리 선택하기를 선택했는가?
- 반응, 다음 상태: 추가 카테고리 선택하기를 선택했을 때만 카테고리 분류를 보여준다.
    추가 카테고리의 입력 요소는 disabled로 비활성화하고, 다시 표시되면 사용됨.

5. 콘텐츠 확인
- 이전과 동일.

6. 볼 컨텐츠 선택
- 행동, 이벤트: 사용자가 원하는 요소(찜목록, 영화 * 시리즈 여부, 카테고리)를 선택한다.
- 반응, 다음 상태: 체크박스를 선택했을 때만 카테고리 분류를 보여준다.
    추가 카테고리 입력 요소는 disabled로 비활성화하고, 다시 표시되면 사용됨

## 테스트 결과
1. label을 눌렀을 때 연결된 입력칸으로 초점이 이동되는 것을 확인함.
2. 안내·글자 수·오류 문장이 이름 입력 칸 가까이에 표시됨.
    상태가 색과 문장으로 구분되며 오류를 수정하면 상태가 갱신되는 것도 확인됨.
3. 추가 카테고리 선택 체크박스를 선택하면 추가 입력 영역이 나타나거나 사라지는 것이 확인됨.
4. 카테고리 영역을 닫으면 선택이 해제되는 것을 확인함.
5. 정보 활용 동의 여부가 정상적으로 브라우저에 저장되는 것을 안내 문구로 확인할 수 있음. 현재 주소창의
    쿼리 스트링(Query String)에 save-error라는 이름의 파라미터가 존재하거나 오류 등으로 인해 저장에 실패했을 경우 오류 문구가 뜨도록 설정했다. (async function persistAgreement(), Ln226)
6. 목록 이름 및 콘텐츠 제목을 수정하고 취소한 다음 다시 수정할 때 저장된 이름이나 제목이 아닌 취소된 내용이 나타나는
    오류 및 콘텐츠 정보 입력에서 2개 이상 카테고리 선택 시 선택 안함으로 저장되는 오류가 수정됐음을 확인함.
